# Тестирование временной сложности алгоритмов (C++)

Данный репозиторий содержит лабораторную работу по исследованию и анализу времени выполнения алгоритмов с различной алгоритмической сложностью (O(1), \(O(\log n)\), O(n), \(O(n \log n)\), O(n²)) в зависимости от объема входных данных.

## 📌 Описание проекта

В ходе работы был написан и скомпилирован код на языке C++, осуществляющий замеры времени выполнения пяти различных базовых операций для массивов (векторов) размерностью от 10 000 до 100 000 элементов с шагом 10 000. 

### Исследуемые алгоритмы:
1. **O(1) (Константная сложность)** — чтение элемента вектора по прямому индексу. Для предотвращения оптимизации со стороны компилятора использован модификатор `volatile`.
2. **\(O(\log n)\) (Логарифмическая сложность)** — классический алгоритм бинарного поиска (Binary Search) элемента в заранее отсортированном массиве.
3. **O(n) (Линейная сложность)** — последовательный проход по массиву для вычисления суммы всех его элементов.
4. **\(O(n \log n)\) (Линеарифмическая сложность)** — сортировка элементов массива с использованием стандартного эффективного алгоритма `std::sort`.
5. **O(n²) (Квадратичная сложность)** — алгоритм поиска дубликатов в неотсортированном массиве с помощью двух вложенных циклов.

## 📊 Результаты замеров

Замеры времени проводились в миллисекундах (мс) с использованием высокоточного таймера `std::chrono::high_resolution_clock`. В репозитории представлены результаты двух независимых запусков программы, подтверждающие теоретические законы распределения сложности.

### Пример итоговой таблицы (Запуск №1)

| N | O(1) (мс) | O(log n) (мс) | O(n) (мс) | O(n log n) (мс) | O(n^2) (мс) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **10 000** | 0.000 | 0.002 | 0.022 | 0.156 | 36.560 |
| **50 000** | 0.001 | 0.000 | 0.090 | 0.834 | 989.017 |
| **100 000** | 0.001 | 0.001 | 0.202 | 1.910 | 3684.854 |

## 📈 Основные выводы анализа

* **Эффективность O(1) и \(O(\log n)\):** Время работы данных алгоритмов стремится к нулю и практически не изменяется при увеличении объема данных в 10 раз. Это делает их самыми быстрыми и масштабируемыми.
* **Пропорциональность O(n):** Линейный алгоритм демонстрирует строго прямую зависимость — время увеличивается ровно во столько же раз, во сколько возрастает размерность выборки (N).
* **Стабильность \(O(n \log n)\):** Алгоритм сортировки показывает незначительное опережение линейного роста, оставаясь высокоэффективным (менее 2 мс для 100 000 элементов).
* **Критический рост O(n²):** Алгоритмы с вложенными циклами демонстрируют взрывной рост времени выполнения. При увеличении входного файла в 10 раз время работы возрастает примерно в **100 раз** (до 3.6 секунд), что делает их неприменимыми для обработки Big Data.

## 🛠 Инструкция по сборке и запуску

Для компиляции программы вам понадобится компилятор с поддержкой стандарта C++11 или выше (например, `g++`).

### Компиляция через терминал:
```bash
g++ -O2 main.cpp -o benchmark
```
*Примечание: Флаг `-O2` включает базовую оптимизацию, однако константная сложность защищена от вырезания инструкцией `volatile`.*

### Запуск:
```bash
./benchmark
```
